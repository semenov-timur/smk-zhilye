# 0004. Ветки: main + develop + короткие ветки изменений

Дата: 2026-11-15 · Статус: принято

## Решение
Упрощённый Git Flow: `main` — продакшен (только релизы с тегами), `develop` —
интеграция и ветка по умолчанию, `change/NNN-slug` — по ветке на изменение.
Релизные ветки — только когда релиз нужно стабилизировать отдельно.
Фичи вливаются в `develop` squash-мерджем, `develop` в `main` — merge commit + тег.
Подробности: `docs/git-workflow.md`.

## Почему
- `develop` даёт место для тестового стенда и показа работы заказчику до релиза.
- Squash держит историю `develop` читаемой: один коммит на изменение,
  детали — в `docs/changes/archive/`.
- Постоянные релизные ветки избыточны для одного разработчика.

## Альтернативы
- Trunk-based (только `main`) — проще, но нет отдельной ветки под тестовый стенд.
- Полный Git Flow с релизной веткой на каждый выпуск — лишняя работа при одном разработчике.
