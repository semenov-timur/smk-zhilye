# 001 — Каркас монорепозитория

> Черновик подготовлен заранее как пример. Перед утверждением проверьте
> требования и ответьте на открытые вопросы.

## Зачем

Получить пустой, но рабочий проект: сайт и админка запускаются одной
командой, связаны между собой, а проверки качества идут автоматически.
На этом каркасе будут строиться все следующие изменения.

## Требования

- Монорепозиторий на pnpm workspaces: `apps/site` и `apps/cms`.
- `apps/site` — Astro в режиме SSR с Node-адаптером, TypeScript strict, Tailwind CSS.
- `apps/cms` — Payload 3 с адаптером PostgreSQL, TypeScript strict.
  Коллекции пока только `users` (доступ к админке) и `media`.
- Сайт получает данные из Payload через REST API; адрес CMS задаётся
  переменной окружения.
- Главная страница сайта — техническая заглушка: название компании и
  статус связи с CMS («CMS: доступна» / «CMS: недоступна»).
- Локальная разработка через Docker Compose: PostgreSQL, CMS, сайт.
  Запуск одной командой из корня.
- Линтер и форматтер для всего репозитория, проверка типов.
- Vitest в `apps/cms` и Playwright в `apps/site`, по одному
  смоук-тесту в каждом.
- CI на каждый pull request в `develop` и `main`: установка, линтер, типы,
  тесты, сборка обоих приложений.
- Корневой `README.md` и раздел «Команды» в `CLAUDE.md` описывают установку,
  запуск, тесты и сборку.
- Все переменные окружения перечислены в `.env.example`.

## Критерии приёмки

- [ ] AC-1: Из чистого клона после `cp .env.example .env` команда
  `docker compose up` поднимает БД, CMS и сайт без ручных шагов. (manual)
- [ ] AC-2: Админка открывается на `http://localhost:3000/admin`, можно
  создать первого пользователя и войти. (manual)
- [ ] AC-3: Сайт открывается на `http://localhost:4321` и показывает
  «CMS: доступна», когда CMS запущена. (e2e)
- [ ] AC-4: При остановленной CMS главная сайта отвечает 200 и показывает
  «CMS: недоступна», а не падает с ошибкой. (e2e)
- [ ] AC-5: Анонимный запрос `GET /api/users` к CMS возвращает 403. (test)
- [ ] AC-6: Команды линтера, проверки типов, тестов и сборки, указанные
  в README, выполняются из корня без ошибок. (manual)
- [ ] AC-7: CI запускается на pull request и проходит на ветке этого изменения. (manual)
- [ ] AC-8: В репозитории нет секретов: `.env` в `.gitignore`, в `.env.example`
  только заглушки. (manual)

## Не входит

- Коллекции контента (услуги, объекты, отзывы, заявки) — отдельное изменение.
- Дизайн, вёрстка, реальные страницы.
- Деплой на сервер, домен, HTTPS.
- Русская локализация админки (отдельной мелкой задачей или в изменении модели контента).

## Открытые вопросы

- Где хостим репозиторий: GitHub или GitLab? От этого зависит формат CI.
- Линтер и форматтер: ESLint + Prettier (стандарт, больше примеров)
  или Biome (один быстрый инструмент)? Предложение — ESLint + Prettier.
- Версия Node.js для проекта: предложение — актуальная LTS.
