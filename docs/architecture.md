# Архитектура

## Обзор

```
Посетитель ──► Сайт (Astro, SSR) ──API──► Payload CMS ──► PostgreSQL
                                             ▲    │
Менеджер ────────────► админка Payload ──────┘    └──► почта, Telegram (заявки)
```

Всё работает в Docker на VPS у российского провайдера.

## Стек

| Слой | Технология | Зачем |
|---|---|---|
| Язык | TypeScript (strict) везде | Один язык для сайта и бэкенда |
| Сайт | Astro, режим SSR (Node-адаптер) | Быстрые контентные страницы, хорошее SEO |
| Интерактивные блоки | React-«острова» в Astro (этап 2) | Калькулятор, фильтры |
| Стили | Tailwind CSS | Единая дизайн-система, быстрая вёрстка |
| Бэкенд и админка | Payload 3 | Модели данных, админка, REST API, права, хуки |
| База данных | PostgreSQL | Через официальный адаптер Payload |
| Тесты | Vitest (модули, интеграция), Playwright (e2e) | |
| Инфраструктура | Docker Compose, Nginx/Caddy, российский VPS | |
| CI | GitHub Actions (уточняется: GitHub или GitLab) | Линтер, типы, тесты, сборка на каждый PR |

Решения и их причины: [decisions/](decisions/).

## Структура репозитория

```
apps/site     — сайт на Astro
apps/cms      — Payload: коллекции, глобальные настройки, хуки
docs/         — продукт, архитектура, дизайн-система, решения, спецификации
.claude/      — скиллы для ИИ-агента
```

## Модель данных (этап 1, предварительно)

Окончательно фиксируется в изменении о модели контента и затем живёт
в `docs/specs/content-model.md`.

| Сущность | Тип в Payload | Основные поля |
|---|---|---|
| Услуги | collection | название, slug, краткое и полное описание, фото, порядок |
| Объекты | collection | название, slug, город, год, площадь, тип заказчика, фото, описание |
| Отзывы | collection | автор, организация, текст, скан письма, опубликован |
| Документы | collection | название, файл (СРО, лицензии и т.п.) |
| Заявки | collection | имя, телефон, сообщение, источник, согласие на ПДн и время согласия |
| Медиа | collection (upload) | фото и файлы |
| Пользователи | collection (auth) | менеджеры с доступом к админке |
| Настройки сайта | global | телефоны, почта, адрес, мессенджеры, реквизиты |
| Главная | global | первый экран, цифры, преимущества |

## Окружения

| Окружение | Где | Назначение |
|---|---|---|
| local | Docker Compose на машине разработчика | Разработка |
| production | VPS в РФ | Боевой сайт smk-zhilye.ru и админка |

Тестовый стенд добавим, если понадобится показывать заказчику работу до релиза.

## Принципы

- Контент — только из CMS, никаких захардкоженных текстов на страницах,
  кроме служебных подписей интерфейса.
- Секреты — только в переменных окружения, шаблон в `.env.example`.
- Персональные данные (заявки) хранятся только в нашей БД в РФ.
- Шрифты и скрипты подключаются локально, без Google Fonts и зарубежных CDN.
